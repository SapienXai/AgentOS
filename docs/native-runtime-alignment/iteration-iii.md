## Dashboard measurements

Each scale uses two browser contexts and ten spaced native session mutations. Both SSE arms observe the same Gateway and application. Update bytes exclude the initial full snapshot. Cold and warm timings measure navigation to the first agent tile in Chrome.

At 50 agents, the largest initial fields were runtimes at 590,416 bytes, tasks at 159,432 bytes, workspaces at 109,993 bytes, diagnostics at 88,320 bytes and agents at 55,874 bytes. The approximate p95 arrival after the most recent native mutation was 1,363 ms for full updates and 1,347 ms for incremental updates. That arms comparison estimates event-to-stream delay. The end-of-window process samples were 488,320 KiB RSS for AgentOS and 2,124,368 KiB for OpenClaw, with instantaneous `ps` CPU readings of 0% for both.

## Consolidated owner acceptance checklist

- In a disposable candidate installation, open **Continue with ChatGPT**. Authorize two test identities, then choose each saved account and run an entitled model. In **Models**, exercise refresh, disconnect and reconnect. Restart the disposable Gateway and repeat. Each success requires a real completed model reply under the selected account. Exercise a disposable cloud API key and the intended local model endpoint through the same product flow.
- In **Agent details → Capabilities → MCP integrations**, add the approved OAuth test server. In **OpenClaw Control UI → Config → MCP**, sign in to that server with an administrator. Run a known harmless tool or read a known test resource through the agent. Return to AgentOS, clear the shared sign-in, verify that the tool asks for authorization again, then reconnect.
- In **Channels**, connect a test Telegram bot, test Discord account and approved test destinations for Slack and WhatsApp when available. Verify inbound routing to the selected workspace and one reply to each approved destination. Disconnect and reconnect each account and confirm the expected readiness transition and restored routing.
- Supply or authorize an isolated Railway candidate project. Install the verified artifact there. Send a disposable message, restart the Gateway in the same service, recreate the service with the same volume, and verify the transcript and account state after each transition.
- Use the candidate artifacts on the remaining physical desktop and mobile platforms. Verify initial launch, operator sign-in, chat and settings through a reconnect. Release signing, public distribution and production cutover require separate authorization after the remaining engineering gates pass.
